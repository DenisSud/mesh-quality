# 3D Mesh Quality Control

Main-stage task (Sber): detect defects on 3D meshes and classify each object as
good/low. Full spec and scoring: [docs/tasks/mesh-quality.md](../../docs/tasks/mesh-quality.md).

- Metric: `10 * F1(quality) + 10 * F1_weighted(artefacts)`
- Deliverables: `submission.csv`, interpretation notebook, presentation
- Main-stage results do not count toward the final winner, but the task returns
  in the final stage with increased complexity.

## State

**Shipped (main stage, 16 Sep 2026):** frozen DINOv3 patch features (6 views ×
8×8 pooled grid + tile mean/max) + 27 geometry features → 4-layer attentive probe
(7.7M trainable, 398 tokens, d=384) → 10 sigmoid defects; `quality` derived as
the all-zero rule; per-label thresholds tuned on OOF probabilities for the task
metric. Two probes (ViT-S/16, ViT-B/16), test probabilities averaged.

- OOF /20: geometry HistGB 10.52, DINOv3-s 13.45, -b 13.30, **fused s+b 13.68**
- Public LB: **13.86** (best upload `s04` in `submissions.csv`)

**Reduction refactor (branch `refactor/mesh-quality-reduction`):** the token
resolution / pooling subsystem is gone — the full-CV ablation matrix put every
variant (`16`/`32` grids, mean+max cells, attention pooling, no summaries)
inside ±0.1 of the shipped 8×8+summaries recipe, so extraction now pools 4×4 at
extraction time into a single 8×8 cache (~2.6 GB instead of 42 GB). The shipped
recipe, checkpoints and thresholds are unchanged; inference is bit-identical to
`main` (verified). Measurements and the reproduction recipe live in the agent
memory note `knowledge/mesh-quality-solution.md`.

The full experiment log, data-fact measurements, ablation study, pipeline-bug
post-mortems and the final-stage plan were moved out of this directory
(`NOTES.md` deleted on 16 Sep) into the agent memory note
`knowledge/mesh-quality-solution.md`.

## Layout

- `main.py` — CLI: `train` | `predict` | `score` | `visualize` | `features` |
  `resubmit` | `fuse` | `logscore` | `deliver` (shared task interface, see
  [AGENTS.md](../../AGENTS.md))
- `src/mesh_quality/` — geometry features, DINOv3 image features (single 8×8
  pooled fp16 cache written at extraction time), attentive-probe model, metric +
  threshold tuning, command handlers, visualization, Colab bundle staging
- `tests/` — CPU pytest suite for the pipeline seams (cache round-trip, token
  layout, metric identity, fusion reproducibility); `uv run pytest` from the
  repo root
- `notebooks/` — jupytext sources for the two graded notebooks
  (`colab_solution`, `interpretation`); `.ipynb` generated by
  `tools/build_notebooks.py`. **Stale vs the cache refactor** (they call
  `extract_split(grid=…)` and read `.npz` caches) — frozen for the main stage,
  fix before regenerating a Colab bundle in the final stage
- `presentation/` — Typst deck (`presentation.typ` → `presentation.pdf`, 19
  slides) and its figures (`tools/make_figures.py`, `tools/analysis_figures.py`);
  revised 17 Sep to lead with the solution, fold the resolution/pooling
  falsification into the ablation slide and compress the pipeline-bug story
- `tools/` — ablations (`hyperparams.py`, `ablation_histgb.py`), cache
  migration (`migrate_npz_cache.py`), figures, `explorer/build_html.py`
  (self-contained HTML data explorer)
- `submissions.csv` + `submissions/` — leaderboard log; per-upload probability
  matrices keep every uploaded CSV regenerable via `resubmit`
- `data/` — provided data (8964 train / 669 test items: PNG collage 1536×1024,
  mesh `.npz`, `train.csv` markup)
- `cache/` — feature caches, checkpoints, probability matrices (gitignored)

**Published Colab bundle (main stage):** hosted in a public Google Drive folder,
<https://drive.google.com/drive/folders/12ttUbp4Bjwx1mFVrdBNkqiZA0YuSRTR_>.
`fetch()` resolves Drive folder/file/viewer links itself (`file/d/<id>` links are
rewritten to the direct-download URL — a raw viewer link used to be saved as an
HTML page). The notebook imports the code *from the bundle*, not this working
tree, so the hosted copy is what reproduces `s04`. To make that snapshot
immune to later repo work, `notebooks/colab_solution.py` pins it: `BUNDLE_URL`
defaults to the exact Drive file (`1HlpL4rR…`) and `BUNDLE_MD5`
(`3712dbbed876e3dbb58ee7244f4236c3`) is checked after download (the zip was
built from `a5d98cb`; the folder link is kept as a commented alternative).
If the pinned file is ever replaced, the notebook stops with an explicit
md5-mismatch message instead of silently running different code. Re-staging with
`deliver` rebuilds the zip and re-checks that its reference probabilities
reproduce `submission.csv`; a new zip means new `BUNDLE_URL`/`BUNDLE_MD5` values.

**Reproducing the shipped submission** (`s04`, md5 `3b7a4525…`): it predates the
cache rework, so it reproduces bit-exactly with the pre-rework code
(commit `7589dc2`) and the legacy fp16 caches in `cache/backup_g8v1/`
(`tools/migrate_npz_cache.py` converts them to the current directory format).
On current code, `fuse` reproduces `cache/fuse_s+b.json` byte-identically, while
`predict` probabilities drift by ~0.02 (a few near-threshold cells) because the
rework switched the probe's GPU inputs from fp32 to bf16.

Run from the repo root: `devenv shell -- uv run python main/mesh-quality/main.py --help`.
The Colab-reproducibility requirement means the pipeline must download data and
install dependencies itself (see the task spec); `notebooks/colab_solution.ipynb`
does exactly that: it pulls the 26.6 GiB `AIC_data.tar` mirror (the official
`test.zip`/`train.zip` via `SOURCE_ARCHIVE = ""`), unpacks PNGs only, re-runs
inference to `submission.csv`, and then demonstrates the full 5-fold training
cycle. `DOWNLOAD_RAW_TRAIN = False` or a `TRAIN_CACHE_URL` feature cache turns
that into a short run when needed.
